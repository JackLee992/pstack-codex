# Design rationale

Keep only the sections that explain the decision:

- Requested behavior and constraints.
- Existing entrypoints, contracts, and ownership to retain.
- Caller usage and proposed types/interfaces.
- Chosen design, meaningful alternatives, and tradeoff.
- Failure, cancellation, retry, and cleanup behavior.
- Concrete verification and remaining assumptions.

References to code and evidence should let a reviewer check the proposal without the conversation history. A design document is not evidence that its implementation or runtime behavior has passed.
