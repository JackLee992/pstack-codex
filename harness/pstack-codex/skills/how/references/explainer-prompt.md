# Synthesize a subsystem explanation

Build a connected explanation from the inspected source and any explorer findings. Resolve conflicting claims against source. Lead with what the subsystem does and where a caller enters, then explain the sequence and ownership needed to change it safely.

Include only the useful parts of: overview, key concepts, runtime flow, file locations, integration seams, and pitfalls. Cite concrete files or symbols, disclose unverified runtime assumptions, and match the reader's experience. Keep the original task's scope; explaining code does not authorize changes.
